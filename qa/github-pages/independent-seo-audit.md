# SEO-аудит трёх вариантов DecoFlowers

Дата: 11 октября 2026. Проверены утверждённые исходники C1 «Внутренний сад», C2 «Предметный арт-журнал», C3 «Зелёная архитектура» в `work/deco-c-1`, `work/deco-c-2`, `work/deco-c-3`. Аудит независимый; изменения и публикация выполняются основным агентом после этого отчёта. Состояние ниже относится к исходникам до SEO-правок.

## Главный вывод

Все три страницы имеют русскоязычный содержательный HTML, один H1, последовательные разделы, настоящие ссылки и фотографии с описаниями. Критическая задача перед переносом на GitHub Pages — единая политика индексации. Сейчас C1 индексируемый по умолчанию, C2/C3 запрещают индексацию и переходы `noindex,nofollow`. Три альтернативных дизайна одного бренда с одинаковыми контактами не должны конкурировать в поиске как три самостоятельных официальных сайта.

Рекомендация до выбора единственного основного сайта: **`noindex,follow` на всех трёх вариантах**, включая будущие GitHub Pages и прежние Sites, если они остаются доступны. `robots.txt` должен разрешать обход, чтобы поисковик увидел `noindex`. Это осознанная политика для публичных вариантов на согласование, а не гарантия попадания в выдачу. Публичные ссылки и социальные превью работают независимо от поисковой индексации.

После выбора основного сайта: индексировать только выбранный адрес, задать ему self-canonical и sitemap; остальные копии оставить `noindex,follow`, либо перенаправить на основной сайт. Не выбирать C1 главным только потому, что он первый в списке. Не делать canonical всех страниц на невыбранный или несуществующий домен.

## Приоритет P0: до публикации

1. Задать `noindex,follow` всем трём страницам. Не добавлять `Disallow: /`: он мешает прочитать метатег. На уровне публичного корня не должно быть страницы с источниками, внутренних отчётов и черновиков. Публиковать только `dist`.
2. После получения реальных GitHub owner/repository/base path добавить абсолютный self-canonical каждому варианту, включая завершающий `/` для directory URL. Это идентификатор конкретного варианта; он не заменяет `noindex`. Все OG URL и schema page URL должны совпадать с ним. Не оставлять тестовые имена или подставлять неизвестный owner.
3. Проверить относительные пути после переноса под `/REPOSITORY/.../`. В текущих HTML/CSS/JS локальные ресурсы используют относительные пути, что подходит для Pages. Каждому опубликованному маршруту нужна реальная папка с `index.html`; SPA fallback отсутствует и не требуется.

## Приоритет P1: метаданные и достоверность

- У всех страниц отсутствуют OG и Twitter card, canonical и JSON-LD. Для каждой добавить `og:type=website`, `og:locale=ru_RU`, уникальные `og:title`, `og:description`, абсолютные `og:url` и `og:image`, описание картинки; Twitter card `summary_large_image` с соответствующими полями. Бренд и Ташкент должны быть понятны из title/description, а название концепции позволяет различать три варианта.
- Для превью использовать уже проверенную реальную фотографию DecoFlowers либо композицию макета без утверждения, что она показывает выполненный клиентский проект. Образ должен быть доступен по абсолютному публичному URL. Проверить размеры, MIME type и читаемость миниатюры. Рекомендуемое соотношение 1.91:1; не вырезать главный предмет из портретной фотографии случайным центровым кропом.
- Добавить JSON-LD только с подтверждёнными фактами: `Florist` или `LocalBusiness`, имя DecoFlowers, телефон `+998900190901`, адрес «массив Аль-Хорезми-1, 9», Ташкент, Узбекистан, и `sameAs: https://www.instagram.com/decoflowersuz/`. `url` — текущий вариант. При использовании WebPage связать её с организацией. Для адреса применять `PostalAddress`, `addressLocality: Ташкент`, `addressCountry: UZ`. Не добавлять рейтинг, отзывы, часы, geo, цены, наличие и историю основания: подтверждений для этих полей в текущем задании нет. Разметка не гарантирует расширенное поисковое представление.
- C3 description сейчас содержит «Дизайн-концепция»; заменить на предметное описание товаров и оформления, если общий публичный стиль исключает такие пояснения. Уникальность описания достигается акцентом на архитектурное озеленение. Это метаданные, UI менять не нужно.
- Сохранить настоящие публичные ссылки на Instagram и телефон. Удаление служебных ссылок на источники не означает удаление контактов бренда. Не добавлять `nofollow` официальному контакту без причины; внешние `target=_blank` уже используют `noopener`.

## Приоритет P1: доступность для робота и progressive enhancement

Chromium с отключённым JavaScript проверен на 1440 × 900 и 390 × 900 через локальный HTTP-сервер. C2/C3: H1 видимый, основные тексты присутствуют, нет горизонтального переполнения. C1: содержательный текст присутствует, на desktop H1 читается; на mobile no-JS CSS уменьшает `.c1-hero` до 1 × 1 px, ширина H1 получается 0. Исправить только no-JS fallback: дать читаемый заголовок перед комнатой. Утверждённую портальную анимацию при наличии JS не менять. Это отдельная проверка от SEO метаданных.

Статические тексты аккордеонов и категорий уже лежат в HTML. Не переносить их целиком в JS или получать лишь после клика. Нативные `details/summary` подходят для содержимого по запросу. Закрытое состояние само по себе не означает, что текста нет в HTML. Динамический фильтр атласа должен продолжать показывать все элементы без JS. Основные ссылки на разделы должны сохранять обычные `href=#id`.

## Приоритет P2: загрузка и Core Web Vitals

- Изображения уже WebP; ниже первого экрана почти везде `loading=lazy`, первый экран без lazy. C1 имеет `fetchpriority=high` для портального кадра и фоновой комнаты. Для C2/C3 можно задать high только основному hero-изображению, не всем фотографиям. При смене источника hero C3 сохранять фактическую геометрию.
- Суммарный размер `dist`: C1 ~6.56 MB, C2 ~6.83 MB, C3 ~8.29 MB. Это размер всех поставляемых файлов, **не объём первой загрузки**. Не выдавать его за LCP или performance score.
- Cormorant TTF ~1.17 MB в C1/C2. `font-display:swap` уже есть. Допустима конвертация в WOFF2 с сохранением кириллицы и лицензии; изменение шрифтовой семьи не требуется. C3 использует только Manrope (AtlasSans), Cormorant в dist не загружается CSS и может быть исключён из публикации только после проверки отсутствия ссылок.
- При дальнейшем улучшении скорости делать responsive варианты больших реальных фото и `srcset/sizes`; пока не ухудшать качество уменьшением всех изображений до мобильного размера. LCP/CLS/INP необходимо измерять на фактическом хостинге. В этом аудите полевых метрик и достоверного Lighthouse score нет.

## Критерии приёмки SEO-правок

1. Три HTML имеют один title, один description, один canonical, `noindex,follow`; URL совпадают с фактическими Pages links, без placeholders.
2. OG/Twitter ссылки абсолютные, изображения реально отвечают HTTP 200 и имеют правильный content-type; у трёх вариантов свои title/description.
3. JSON-LD корректный JSON с указанным типом и подтверждёнными контактами; отсутствуют выдуманные rating, review, price, openingHours и geo.
4. `robots.txt` не блокирует чтение noindex. Для неиндексируемых альтернатив не нужна submission в Search Console и sitemap не следует выдавать за индексируемую карту.
5. Все локальные URL под Pages base path отвечают 200. `source-notes.html`, asset-ledger, internal QA и черновики не присутствуют в публикуемом дереве.
6. Intrinsic размеры всех статических img соответствуют фактическим файлам; динамический hero C3 не сдвигает блок при переключении.
7. 1440/390: основной контент читаем с JS и без него; C1 mobile no-JS H1 исправлен. Нет горизонтального переполнения. Reduced motion и меню/аккордеоны/gallery/form продолжают работать.
8. Git commit и опубликованный artifact соответствуют одной проверенной версии; последующее изменение основного индексируемого домена требует новой проверки политики всех копий.
